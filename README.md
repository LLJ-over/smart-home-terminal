# 基于 ESP32 的智能家居环境监测与远程控制终端 (Wokwi 仿真)

> 一个端到端的 IoT 物联网入门项目：包含传感器采集、本地 OLED 显示、Wi-Fi 联网、MQTT 云端通信及远程设备控制。

##  核心功能
- **本地感知**：基于 DHT22 实时采集温湿度，并在 SSD1306 OLED 屏幕上刷新显示。
- **数据上云**：通过 Wi-Fi 接入 MQTT Broker，每两秒上传一次数据且以 JSON 格式定时发布环境数据。
- **远程控制**：订阅云端控制指令（`home/cmd/ll_test`），实现对执行器（LED/继电器）的远程开关。
- **可靠性设计**: 包含 Wi-Fi 断线自动重连、MQTT 掉线重试；实现 WiFi 连接 15 秒超时机制，并优化弱网下的 MQTT 重连逻辑（防刷屏），防止设备死机卡死。 	

##  技术栈
- **硬件平台**：ESP32 (Wokwi 虚拟仿真)
- **编程语言**：C/C++ (Arduino Framework)
- **通信协议**：MQTT, I2C, Wi-Fi
- **传感器与执行器**：DHT22, SSD1306 OLED, LED
- **工程化重构**: 采用模块化设计，将硬件驱动、业务逻辑与网络通信拆分为独立文件，提升代码可维护性。

## 设计取舍 (Design Trade-offs)
- **为什么使用公共 MQTT Broker？**
  在 V1 阶段，核心目标是验证“端-云-端”的通信链路与 JSON 数据解析，使用 `broker.emqx.io` 可以零成本、零配置地快速跑通业务逻辑。后续 V2 阶段若增加多设备鉴权与数据安全需求，将自建私有 MQTT 服务器。
- **为什么目前不画 PCB 打样？**
  目前项目定位为“软件逻辑与通信协议验证”。Wokwi 仿真已能覆盖 90% 的代码逻辑。在硬件电路未定型、无实物联调需求之前，画 PCB 会增加试错成本。后续实机联调阶段再引入原理图与 PCB 设计。
